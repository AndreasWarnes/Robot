
# Robot

ROS 2 workspace for a (future autonomous) tracked robot with two independently driven tracks.

The first milestone is to drive the tracks forward and backward in simulation (Gazebo) using a PlayStation controller. The software is structured so the simulation can later be replaced by real motor drivers without changing the teleop or navigation parts.

> **Status:** early development. The workspace structure is in place; the robot model, simulation and teleop launch files are being added.

## Requirements

| Component | Version |
|---|---|
| OS | Ubuntu 24.04 (Noble). On Windows, use WSL2 with Ubuntu 24.04 |
| ROS 2 | Jazzy Jalisco |
| Simulator | Gazebo Harmonic (installed via `ros-jazzy-ros-gz`) |

Other combinations (e.g. Humble + Fortress, or Debian) are not supported and will likely require building from source.

## Setup

### 1. Install ROS 2 Jazzy

Follow the official guide: <https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html>

Install `ros-jazzy-desktop` and `ros-dev-tools`, then add this to `~/.bashrc`:

```bash
source /opt/ros/jazzy/setup.bash
```

### 2. Install project dependencies

```bash
sudo apt update
sudo apt install -y \
  ros-jazzy-ros-gz \
  ros-jazzy-joy \
  ros-jazzy-teleop-twist-joy \
  ros-jazzy-xacro
```

Verify the installation:

```bash
rviz2      # should open a window
gz sim     # should open the Gazebo launcher
```

### 3. Clone the repository

Clone into the Linux filesystem (`~/`), **not** under `/mnt/c/...` on WSL, otherwise builds are very slow.

```bash
cd ~
git clone <repo-url> Robot
cd Robot
```

### 4. Install remaining dependencies with rosdep (optional)

Once the `package.xml` files list their dependencies, rosdep can install anything missing:

```bash
sudo rosdep init        # first time on this machine only
rosdep update
rosdep install --from-paths src --ignore-src -r -y
```

### 5. Build

Always build from the workspace root (`~/Robot`), not from `src/`.

```bash
cd ~/Robot
colcon build --symlink-install
source install/setup.bash
```

To source the workspace automatically in every new terminal:

```bash
echo "source ~/Robot/install/setup.bash" >> ~/.bashrc
```

`--symlink-install` means changes to existing launch, YAML and URDF files take effect without rebuilding. **New** files, new packages, and changes to `CMakeLists.txt` or `package.xml` require a rebuild.

## Running

> These commands work once the corresponding launch files have been added.

Start everything (simulation + teleop):

```bash
ros2 launch tracked_robot_bringup sim_teleop.launch.py
```

Or run the parts separately:

```bash
ros2 launch tracked_robot_gazebo sim.launch.py
ros2 launch tracked_robot_teleop teleop.launch.py
```

Test the robot without a controller by publishing a velocity command:

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5}}"
```

### PlayStation controller on WSL

USB devices are not passed through to WSL by default. Use [usbipd-win](https://github.com/dorssel/usbipd-win) to attach the controller, then check that it works:

```bash
ros2 run joy joy_node
ros2 topic echo /joy
```

The teleop configuration uses an **enable button (deadman switch)**: the robot only moves while the button is held.

## Project structure

```
Robot/
├── .gitignore
├── README.md
├── docs/                              # notes, decisions, TODO
├── scripts/                           # helper scripts (e.g. setup_wsl.sh)
└── src/
    ├── tracked_robot_description/     # what the robot is
    │   ├── urdf/                      # xacro/URDF model files
    │   ├── meshes/                    # CAD meshes (later)
    │   └── rviz/                      # RViz configurations
    ├── tracked_robot_gazebo/          # simulation only
    │   ├── worlds/                    # Gazebo world files (.sdf)
    │   ├── config/                    # ROS <-> Gazebo bridge config
    │   └── launch/                    # starts Gazebo, spawns the robot
    ├── tracked_robot_teleop/          # manual control
    │   ├── config/                    # controller mapping, speed limits
    │   └── launch/                    # joy_node + teleop_twist_joy
    └── tracked_robot_bringup/         # "start everything" launch files
        └── launch/
```

`build/`, `install/` and `log/` are generated by `colcon build` and are ignored by git.

### Packages

| Package | Purpose |
|---|---|
| `tracked_robot_description` | Physical definition of the robot: links, joints, mass/inertia, visual and collision geometry, sensor mounting points. Independent of simulator vs. real hardware. Used by `robot_state_publisher` (TF), RViz and Gazebo. |
| `tracked_robot_gazebo` | Everything that only makes sense in simulation: world files, starting Gazebo, spawning the robot, and the ROS-Gazebo topic bridge. Replaced by hardware drivers on the real robot. |
| `tracked_robot_teleop` | Maps controller input to `/cmd_vel`. Works identically in simulation and on the real robot. |
| `tracked_robot_bringup` | Top-level launch files that combine the other packages. |

Rule of thumb: if it applies to the robot in both simulation and reality, it belongs in `description`. If it only applies to the simulation, it belongs in `gazebo`.

### Data flow (current milestone)

```
PS controller → joy_node → /joy → teleop_twist_joy → /cmd_vel
    → ros_gz_bridge → Gazebo DiffDrive plugin → tracks move
```

The `/cmd_vel` topic is the interface between control and drive. Later, the Gazebo part is replaced by a node that converts `cmd_vel` to left/right track speeds and talks to real motor drivers.

### Adding files to a package

These packages use `ament_cmake`. Every directory with files that ROS must find at runtime has to be listed in that package's `CMakeLists.txt`, above `ament_package()`:

```cmake
install(DIRECTORY launch config
  DESTINATION share/${PROJECT_NAME})
```

Only list directories that exist in that package, otherwise the build fails. Dependencies should be declared in `package.xml` (`<exec_depend>`), so `rosdep` can install them.

## Conventions

- **Units:** SI everywhere (m, m/s, rad/s).
- **Frames:** REP-103/105. x forward, y left, z up. Frames: `base_link`, `odom`, `map`.
- **Simulation time:** all nodes in simulation run with `use_sim_time:=true`, and `/clock` is bridged from Gazebo.
- **Parameters** (track width, separation, max speed, ...) live in YAML files, not in code.
- **Safety:** teleop always requires an enable button. Velocity limits are set in config.

## Git workflow

- Keep commits small and descriptive.
- Work on feature branches, merge into `dev`.
- Do not commit large meshes or binaries without Git LFS.
- Line endings are LF. Add a `.gitattributes` with `* text=auto eol=lf` if collaborating from Windows.

## Troubleshooting

| Problem | Fix |
|---|---|
| `ros2: command not found` | Run `source /opt/ros/jazzy/setup.bash` |
| Package not found after build | Run `source ~/Robot/install/setup.bash` |
| `gz: command not found` | `sudo apt install ros-jazzy-ros-gz` |
| No GUI windows on WSL | Windows 11 (or recent Windows 10), run `wsl --update` in PowerShell |
| Gazebo slow or black screen | Update the Windows GPU driver; as a fallback `export LIBGL_ALWAYS_SOFTWARE=1` |
| Build fails on `install(DIRECTORY ...)` | The listed directory does not exist in that package; create it or remove it from the list |
